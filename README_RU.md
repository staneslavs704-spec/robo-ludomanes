# ROBO LUDOMANES — новая серверная основа

Проект разделён на Telegram-бота, Mini App и API. Локально можно проверять на SQLite в Termux. Для публичного запуска используйте VPS и PostgreSQL через Docker Compose.

## Что реализовано

- Авторизация Mini App через криптографическую проверку `Telegram.WebApp.initData`; переданный браузером `user_id` не используется как источник доверия.
- Регистрация пользователей и рефералов через `/start ref_TELEGRAM_ID`.
- Баллы за действительно нового пользователя; одна регистрация засчитывается только один раз.
- Бесплатная прокрутка за каждые 3 приглашения (число настраивается).
- Три рулетки: бесплатная, за баллы и платная.
- Результат, баланс, списания и призы определяются сервером.
- Идемпотентность прокруток по `request_id`, чтобы повторный сетевой запрос не списал попытку второй раз.
- Платная попытка покупается через Telegram Stars (`XTR`). Mini App открывает нативный счёт Telegram, а попытка начисляется только после `successful_payment`, а не после нажатия кнопки оплаты. Администратор может посмотреть платежи через `/payments` и вернуть неиспользованную попытку командой `/refund ID`.
- Задание подписки проверяется через `getChatMember`; бот должен быть администратором канала.
- NFT-приз выпадает только из фактически добавленного запаса подарков. Победа создаёт персональную заявку; произвольный ID чужого подарка принять нельзя.
- Админ-команды `/stats`, `/addgift`, `/giftstock`, `/fulfill`, `/payments`, `/refund`.
- `/paysupport` для обращений по оплатам.

## 1. Подготовка в Termux

Установите Python и системные инструменты. Для автоматической установки зависимостей после распаковки можно запустить `bash install_termux.sh`; ниже приведён ручной вариант:

```bash
pkg update -y && pkg upgrade -y
pkg install python git nano clang libffi openssl -y
```

Распакуйте проект, перейдите в папку `robo_ludomanes` и выполните:

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip setuptools wheel
pip install -r requirements.txt
cp .env.example .env
nano .env
```

Откройте бота в Telegram и отправьте ему `/start` (это также позволит боту писать администратору об NFT-заявках и оплатах). Заполните как минимум:

- `BOT_TOKEN` — токен из BotFather;
- `ADMIN_ID` — ваш Telegram ID числом;
- `WEBAPP_URL` — публичный HTTPS-адрес Mini App. Для локального теста без публичного HTTPS можно проверять API, но Telegram Mini App не откроется с обычного `http://` адреса.

Локальная установка через `requirements.txt` использует SQLite и не требует компиляции драйвера PostgreSQL. Для публичного VPS-деплоя Docker дополнительно устанавливает `asyncpg` через `requirements-vps.txt`.

Для локального запуска оставьте SQLite:

```env
DATABASE_URL=sqlite+aiosqlite:///./database.db
```

## 2. Запуск в Termux

Нужны два процесса — API и бот. Откройте две сессии Termux.

**Сессия №1 — API:**

```bash
cd ~/robo_ludomanes
source .venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

**Сессия №2 — бот:**

```bash
cd ~/robo_ludomanes
source .venv/bin/activate
python bot.py
```

Проверка API: откройте `http://127.0.0.1:8000/health`. Ожидаемый ответ: `{"status":"ok","service":"robo-ludomanes"}`. Для проверки базы данных также доступен `/ready`.

Для проверки Mini App в самом Telegram нужен доступный из интернета HTTPS URL. Не публикуйте порт Termux напрямую без HTTPS и не рассчитывайте на Serveo как на постоянную инфраструктуру. Для временного теста используйте HTTPS-туннель, а для запуска на аудиторию — VPS с доменом и TLS.

## 3. Настройка канала для задания

Добавьте бота администратором в канал. В `.env` укажите:

```env
REQUIRED_CHANNEL=@имя_канала
CHANNEL_URL=https://t.me/имя_канала
POINTS_FOR_CHANNEL=50
```

Перезапустите API и бота. Если бот не администратор канала, Telegram не гарантирует корректную проверку подписки.

## 4. Добавление NFT-подарков

В личном чате с ботом от администратора:

```text
/addgift Название подарка | https://ссылка-на-подарок | https://ссылка-на-изображение
```

Изображение необязательно. Посмотреть запас:

```text
/giftstock
```

Администратор получает уведомление о заявке. После фактической выдачи отметьте её:

```text
/fulfill ID_ЗАЯВКИ
```

Не добавляйте в запас подарки, которыми проект не располагает.

## 5. Переход на VPS

1. Направьте домен на VPS и настройте HTTPS через Caddy, Nginx + Certbot или аналогичный reverse proxy.
2. Установите Docker Engine и Docker Compose plugin.
3. Создайте `.env` на VPS на основе `.env.example`.
4. В `WEBAPP_URL` укажите HTTPS адрес Mini App.
5. Установите `POSTGRES_PASSWORD` в случайный длинный пароль (например, результат `openssl rand -hex 32`).
6. Запустите:

```bash
docker compose up -d --build
```

7. Reverse proxy должен проксировать HTTPS-трафик на `127.0.0.1:8000`.
8. Проверьте `https://ВАШ-ДОМЕН/health`, затем откройте `/start` у бота.

Пример значения `POSTGRES_PASSWORD` генерируйте отдельно, например `openssl rand -hex 32`. Не используйте примерный или простой пароль.

## 6. Правила игры и настройки

| Переменная | Назначение | По умолчанию |
|---|---|---:|
| `STARS_PER_SPIN` | Цена одной платной попытки | 50 Stars |
| `PAID_WHEEL_ENABLED` | Разрешить платную рулетку после правовой проверки | false |
| `QUEST_SPIN_COST` | Стоимость рулетки за баллы | 100 баллов |
| `REFERRALS_PER_FREE_SPIN` | Приглашений на бесплатную попытку | 3 |
| `POINTS_PER_REFERRAL` | Баллы за нового реферала | 10 |
| `POINTS_FOR_CHANNEL` | Баллы за подписку | 50 |

Платная рулетка по умолчанию отключена (`PAID_WHEEL_ENABLED=false`). Включайте её только после проверки местных законов, правил Telegram и юридической модели призов. Если механика с оплатой и случайными призами подпадает под регулирование азартных игр или лотерей, одного технического решения недостаточно. После согласования можно установить `PAID_WHEEL_ENABLED=true`.

Текущая таблица шансов при наличии подарков: 56 весовых долей — пустой результат, 40 — баллы (10/25/50 с разными весами), 4 — NFT. Если запас NFT пуст, NFT-сектор не участвует в розыгрыше.

## 7. Проверка перед публичным запуском

```bash
python -m unittest discover -s tests -v
python -m compileall app bot.py
```

Обязательно проведите тестовые оплаты через тестовое окружение Telegram Stars, тесты повторных запросов, одновременных прокруток, подписки на канал, возвратов и восстановления базы из резервной копии.

## Важно перед запуском на 5–7 тысяч пользователей

Эта сборка — рабочая стартовая версия с базовыми защитами, а не заверенный аудитом финансовый продукт. До публикации необходимо:

- заменить тестовый токен, который ранее находился в исходном коде, через BotFather; хранить новый только в `.env`/секретах VPS;
- поставить HTTPS и домен; не запускать публичный сервис через Flask development server или постоянный Serveo-туннель;
- настроить ежедневные резервные копии PostgreSQL и проверить восстановление;
- добавить миграции схемы БД (Alembic) до дальнейших обновлений;
- провести нагрузочное тестирование с профилем одновременных пользователей, а не только по общему количеству регистраций;
- проверить условия розыгрыша, правила возвратов, поддержку платежей и юридические требования к механике призов в регионе запуска.

В PostgreSQL выставлен пул соединений API/бота (10 основных + до 20 дополнительных соединений на процесс). У проекта нет Redis, потому что для базовой нагрузки 5–7 тысяч зарегистрированных пользователей он не обязателен. Его можно добавить при реальном росте нагрузки — например для распределённого rate limiting и фоновых задач.

## 8. Резервное копирование и кнопка Mini App

На VPS резервную копию PostgreSQL можно создать так:

```bash
bash backup_db.sh
```

Для ежедневного запуска настройте cron на VPS и храните копии ещё и вне самого сервера. Периодически проверяйте восстановление из копии. Не используйте `docker compose down -v`, если не хотите удалить том с базой данных.

После того как домен и HTTPS готовы, в BotFather можно дополнительно настроить Menu Button: `/setmenubutton` → выбрать бота → указать текст кнопки и `WEBAPP_URL`. Основная кнопка открытия приложения уже отправляется командой `/start`.

Файл `Caddyfile.example` — минимальный пример reverse proxy для Caddy на VPS. Замените `your-domain.example` на свой домен; DNS должен вести на VPS, а входящие порты 80 и 443 должны быть доступны.
